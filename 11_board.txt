 <사용 방법>
   1. 10_board.txt의 SQL 쿼리를 DB(H2 또는 Oracle)에서 실행하여 테이블을 생성
   2. 상단 네비게이션 바의 [게시판] 버튼을 클릭하여 기능을 확인
   3. 게시판 내부의 탭을 통해 카테고리를 이동하며 테스트

<첨부파일>
첨부파일 자체가 DB에 직접 저장되는 방식이 아니라 "서버의 실제 저장 공간(내 컴퓨터/서버 하드디스크)"에
  저장되고, DB에는 그 파일이 어디에 어떤 이름으로 있는지에 대한 "정보"만 저장
1. DB 관리 효율성: 파일 자체(이미지, 문서 등)를 DB에 통째로 넣으면(BLOB 방식), DB 용량이 너무 커져서 전체적인 시스템
      속도가 매우 느려집니다.
2. 성능: 파일을 하드디스크에서 바로 읽어오는 것이 DB에서 데이터를 추출하는 것보다 훨씬 빠릅니다.
실제 작동 방식:
   1. 서버 저장소 (물리적 파일): BoardWriteController에서 지정한 upload/board라는 폴더 안에 실제 파일이 저장됩니다. 이때
      이름이 겹치지 않도록 UUID라는 고유 번호가 붙어서 저장됩니다.
   2. 데이터베이스 (파일 정보): BOARD_FILE 테이블에는 다음 정보만 들어갑니다.
       * ORG_NAME: 사용자가 올린 원래 파일 이름 (예: 보고서.pdf)
       * SAVED_NAME: 서버에 저장된 실제 이름 (예: a1b2c3d4_보고서.pdf)
       * FILE_SIZE: 파일의 용량

  따라서 나중에 다운로드할 때는 DB에서 SAVED_NAME을 찾아 서버 폴더에 있는 진짜 파일을 사용자에게 보내주는 원리.
  참고: 현재 코드는 getServletContext().getRealPath("/upload/board")를 사용하여 프로젝트가 실행되는 서버 내부 경로를
  사용. 나중에 실제 배포 시에는 서버의 특정 절대 경로(예: C:/upload/)로 설정을 변경하는 것이 파일 유실을 방지
 지금은 테스트용이므로 현재 설정으로도 충분히 작동

현재 코드상으로는 서버가 실행되고 있는 프로젝트의 '배포 폴더' 내부에 저장됩니다.

사용자가 작업 중인 src/main/webapp 폴더가 아니라, 톰캣(Tomcat) 서버가 프로젝트를 실행하기 위해
 복사해둔 임시 배포 경로입니다.

저장 위치의 특징
   1. 위치: 보통 이클립스 기준 워크스페이스/.metadata/.plugins/.../wtpwebapps/프로젝트명/upload/board와 같은 경로에
      저장
   2. 장점: 별도의 서버 설정 없이 바로 실행해볼 수 있어 편리
   3. 단점 (주의사항): 서버를 'Clean' 하거나 프로젝트를 다시 빌드(Redeploy)할 경우, 톰캣이 배포 폴더를 새로 만들면서
      기존에 업로드했던 파일들이 삭제될 수 있음.

권장하는 개선 방법
  만약 팀 프로젝트에서 파일이 사라지지 않게 영구적으로 보관하고 싶다면, BoardWriteController.java와
  FileDownloadController.java의 저장 경로를 내 컴퓨터의 특정 절대 경로로 고정하는 것이 좋음

예를 들어, 소스 코드를 다음과 같이 수정할 수 있습니다:
   1 // 기존 코드
   2 // String uploadPath = getServletContext().getRealPath("/upload/board");
   3
   4 // 권장 코드 (예: 윈도우 환경)
   5 String uploadPath = "C:/groupware_uploads/board";

이렇게 하면 서버를 껐다 켜거나 새로 배포해도 파일이 C:/groupware_uploads 폴더에 그대로 남아있게 됩니다.
  지금 바로 이 방식으로 수정을 도와드릴까요, 아니면 현재의 임시 경로 방식을 유지할까요? (현재 방식은 테스트용으로는 가장
  간편합니다!)

폴더는 파일이 처음 업로드될 때 자동으로 생성

  BoardWriteController.java의 다음 로직 때문

   1 // 1. 저장할 경로 계산
   2 String uploadPath = getServletContext().getRealPath("/upload/board");
   3
   4 // 2. 해당 폴더가 있는지 확인
   5 File uploadDir = new File(uploadPath);
   6
   7 // 3. 없으면 폴더를 새로 만듦 (mkdirs)
   8 if (!uploadDir.exists()) uploadDir.mkdirs();

   1. 동적 생성: 아직 게시판에 파일을 첨부해서 글을 쓰지 않았다면 폴더가 아직 생성되지 않은 상태
   2. 경로의 비밀: getRealPath를 쓰면 실제 소스 코드 폴더(src/main/webapp)가 아니라, 톰캣이 실행 중인 내부 작업 폴더에
      생깁니다. 그래서 이클립스나 탐색기에서 프로젝트 폴더만 봐서는 찾기 어려움

  1. 이클립스(Eclipse)를 통해 실행 중인 경우
   * [워크스페이스 폴더]\.metadata\.plugins\org.eclipse.wst.server.core\tmp0\wtpwebapps\Groupware\upload\board
       
  2. 일반 톰캣 서버에 직접 배포한 경우
   * [톰캣 설치 경로]\webapps\Groupware\upload\board

  1. 파일 종류 (확장자)
   * 제한 없음: 현재 코드에는 특정 확장자를 막는 로직이 포함되어 있지 않습니다.
   * 다양한 파일 가능: 이미지(jpg, png), 문서(pdf, docx, hwp), 압축파일(zip), 텍스트(txt) 등 모든 종류의 파일을
     업로드하고 다운로드할 수 있습니다.

  2. 크기 제한 (용량)
  BoardWriteController.java 상단에 설정된 @MultipartConfig에 따라 엄격하게 제한됩니다:
   * 개별 파일당 최대 10MB: 한 개의 파일이 10MB를 넘으면 서버에서 거부합니다.
   * 전체 요청 최대 15MB: 한 번에 여러 파일을 올릴 때, 모든 파일의 용량 합계가 15MB를 넘을 수 없습니다.
   * 메모리 임계값 1MB: 1MB 이하의 작은 파일은 메모리에서 바로 처리하고, 그보다 크면 서버의 임시 디렉토리를 거쳐
     저장하여 서버 부하를 줄입니다.

  3. 개수 제한
   * 다중 업로드 지원: <input type="file" name="files" multiple> 속성을 사용하여 한 번에 여러 개의 파일을 선택해서 올릴
     수 있습니다.

  4. 기타 특징
   * 파일명 중복 방지: 같은 이름의 파일을 올려도 서버에서는 UUID(고유 번호)를 붙여서 저장하므로, 기존 파일이
     덮어씌워지거나 충돌할 걱정이 없습니다.
   * 보안: 실행 파일(.exe, .jsp 등)에 대한 차단 로직은 현재 없으므로, 실제 운영 환경이라면 추후에 화이트리스트(허용된
     확장자만 허용) 방식을 추가하는 것이 안전합니다.
