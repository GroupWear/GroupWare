<초기세팅>
워크스페이스 위치에서 우클릭 - git bash - git clone [주소] 후 해당 폴더로 진입해서 git bash 다시 열기


<주의사항>
-git bash 맨 우측에 뜨는 항상 현재 브랜치 상태 체크하면서 입력

-PR 대기 중에는 푸시(Push) 멈추기
본인 브랜치에서 main으로 코드를 합쳐달라고 PR을 올린 상태라고 가정해 보겠습니다. 이때 팀장이 아직 PR을 승인(Merge)하지 않았는데, 본인 브랜치에 새로운 작업을 해서 또 push를 해버리면 안 됩니다. PR이 열려 있는 상태에서 동일한 브랜치에 push를 하면, 새로 올린 코드까지 기존 PR에 자동으로 섞여 들어가 버립니다. 따라서 PR을 올렸다면 main에 코드가 무사히 합쳐진 것을 확인한 뒤에 다음 작업을 이어가는 것이 안전합니다.

<일반적인 사용방법>
#최신화
팀원들이 main 브랜치에 합쳐둔 최신 코드를 내 로컬 컴퓨터로 가져와서 동기화
1. git checkout main (main 브랜치로 이동)
2. git pull origin main (깃허브에 있는 최신 main 코드를 내 컴퓨터로 다운로드)
3. git checkout 개인브랜치 (다시 내 개인 작업 브랜치로 이동)
4. git merge main (방금 다운받은 최신 main 코드를 내 개인 브랜치에 병합하여 충돌을 미리 예방)

#커밋
개인 브랜치에서 맡은 기능을 개발
의미 있는 기능 단위나 수정 사항이 생길 때마다 세이브 포인트(커밋)을 생성
1. 이클립스에서 코드 작성 및 테스트 진행
2. git add . (변경된 파일들을 깃 장바구니에 담기)
3. git commit -m "게시판 목록 조회 기능 추가" (작업 내용 메모와 함께 로컬에 확정)

#기능 개발 완료 후
맡은 기능 개발이 완전히 끝났거나, 팀원들에게 코드를 공유하고 리뷰를 받아야 할 때 내 컴퓨터의 코드를 깃허브로 올려보내는 단계
1. git push origin 개인브랜치 (내 컴퓨터의 커밋 내역을 깃허브의 개인 브랜치 공간으로 업로드)
2. 깃허브(GitHub) 웹사이트 접속
3. 깃허브 화면에서 내 개인 브랜치의 코드를 main 브랜치에 합쳐달라는 Pull Request (PR) 생성
4. 팀원들이 코드를 읽어보고 문제가 없다고 승인(Approve)하면 main브랜치에 최종 병합(Merge)

#병합 완료 후
코드가 main에 무사히 합쳐졌다면, 다음 새로운 기능을 개발하기 위해 다시 1번 단계로
1. git checkout main
2. git pull origin main (내 코드가 합쳐진 최신 상태를 다시 다운로드)
3. 새로운 작업을 위해 개인 브랜치로 이동 후 다시 개발 시작

#개인과 팀 프로젝트의 병합 루틴
- 나 혼자 하는 프로젝트: git checkout main ->git merge 개인브랜치 -> git push origin main - **팀 프로젝트 (권장 방식): 내 개인 브랜치 상태에서 git push origin 개인브랜치 -> 깃허브 웹사이트에 접속해서 Pull Request 생성 -> 팀원 승인 후 깃허브 웹 상에서 main으로 Merge 버튼 클릭


#집 컴퓨터와 학원 컴퓨터 간의 코드 동기화 (이어하기) 방법

[작업을 마칠 때:]
집에서 하던 코딩을 멈추고 깃허브에 작업 내역을 백업(업로드)합니다.
1. git add .
2. git commit -m "집에서 00기능 작업 중간 저장"
3. git push origin 본인브랜치

[작업을 시작할 때:]

코드를 단 한 줄이라도 치기 전에, 가장 먼저 집에서 올려둔 최신 코드를 다운로드하여 상태를 똑같이 맞춰줍니다.

1. git checkout 본인브랜치 (현재 위치가 본인 브랜치인지 확인 및 이동)
2. git pull origin 본인브랜치

#깃허브 Pull Request (PR) 단계별 가이드
로컬(내 컴퓨터)에서 git push origin 본인브랜치를 성공적으로 마친 직후, 깃허브 웹사이트에서 진행하는 순서입니다.

### 1. PR 생성 화면 진입

1. 깃허브의 팀 프로젝트 저장소(Repository) 페이지에 접속합니다.
2. 코드를 방금 푸시했다면, 코드 목록 바로 위에 연두색 알림창과 함께 초록색 Compare & pull request 버튼이 자동으로 떠 있습니다. 이 버튼을 클릭합니다.
(만약 이 버튼이 안 보인다면, 상단 메뉴의 Pull requests 탭을 누른 뒤 초록색 New pull request 버튼을 클릭합니다.)

### 2. 브랜치 병합 방향 확인

코드를 어디서(출발) 어디로(도착) 합칠지 설정하는 단계입니다.

1. 왼쪽의 base 드롭다운을 main으로 설정합니다. (코드가 도착할 뼈대 브랜치)
2. 오른쪽의 compare 드롭다운을 본인브랜치로 설정합니다. (내가 작업해서 방금 올린 브랜치)
3. 화면에 'Able to merge'라는 녹색 체크 표시가 뜨는지 확인합니다. (충돌이 없다는 뜻입니다.)
4. 우측에 있는 초록색 Create pull request 버튼을 클릭합니다.

### 3. PR 제목과 본문 작성

팀원들에게 내가 어떤 코드를 어떻게 짰는지 설명하는 단계입니다.

1. Title (제목): 어떤 기능을 작업했는지 명확하게 적습니다. (예: 예약 페이지 시간 선택 기능 및 더미 세션 연동)
2. Write (본문): 세부적인 변경 사항이나, 팀원들이 코드 리뷰를 할 때 참고해야 할 사항을 적습니다.
3. 작성을 마쳤다면, 우측 하단의 초록색 Create pull request 버튼을 클릭합니다.
(여기까지 하면 PR 등록이 완료되어 팀원들이 코드를 리뷰할 수 있는 대기 상태가 됩니다.)

### 4. 최종 병합 (Merge)

팀원들이 코드를 읽어보고 문제가 없다고 판단했을 때, 실제 main 브랜치에 코드를 합치는 마지막 단계입니다. (프로젝트 규칙에 따라 본인이 누를 수도 있고, 팀장이 누를 수도 있습니다.)

1. PR 화면 맨 아래로 내려가서 초록색 Merge pull request 버튼을 클릭합니다.
2. 버튼이 바뀌면 한 번 더 초록색 Confirm merge 버튼을 클릭하여 확정합니다.
3. 'Pull request successfully merged and closed'라는 보라색 아이콘 알림이 뜨면 성공입니다.
